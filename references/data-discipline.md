## 1. 数字的来源分级

| 级别 | 例子 | 允许的写法 |
|---|---|---|
| 可计算 | 节点数、边数、层数、消费者数、分支数 | 脚本算，产物里注入 |
| 可grep | 「没有 Agent 节点」 | 附命令与命中数 |
| 需推断 | 「首个命中即停止」 | 写明依据是引擎通用语义，真源里没有注释 |
| 不可知 | 运行时取值、外部子图内部、是否已部署 | 写 `?`，不许编 |

问自己：*这个数字明天会不会变？* 会变的一律走脚本，不走字面量。

**口径先于数字。**「52 节点」必须能回答：含不含便签？含不含虚拟起止点？
把口径写在页眉，比在脚注里解释省事得多。

## 2. 锚点：file:line 的写法

每个节点块带 `ls`/`le`（解析时记录），详情页显示成 `v1.7.0.yml:1780-1908`。三条规矩：

- 行号来自解析，不来自人眼
- 核对用脚本（Python 逐区间断言包含该节点 id），不要用 shell 循环——zsh 不做词分割会得到假阴性
- 区间会随真源升版漂移。产物页眉写清真源路径与版本，读者才能自己对

## 3. 「没有」也是一种结论

负向结论比正向更容易错，因为「我没找到」和「确实没有」经常被混写。每条负向结论要能说出扫描范围：

- 写法：`按 52 个节点的全部 value_selector、条件变量、{{#x.y#}} 文本引用扫描，读它的下游为空`
- 不写：`这个输出没人用`

负向结论的三件套：**扫描范围 + 判据 + 还没排除的可能**。
最后一项常常是：图外的前端、运行日志、人工配置——这些本图看不到，必须承认。

## 4. 结构化脱敏

脱敏表本身是敏感物。规则：

- **不写字面量清单**。按形状识别：内网主机（`.int.` / `.internal` / 私网 IP）、
  变量名含 `secret|key|token|password|sign` 且值是 16+ 长串的赋值、带 `user:pass@` 的连接串、
  工具配置里的 `hook_key` 一类字段
- 推导脚本只打印「命中几类、各几条」，**不打印取值**
- 表文件 gitignore；产物扫一遍、生成器目录也扫一遍（`scripts/leak_scan.py`，它会读目录的 `.gitignore`
  并把被忽略的中间物跳过，同时打印跳过了哪些——不打印的话，「0 命中」和「我没扫」分不清）
- 扫描器自己的输出要打码——它也会被贴进日志

环境变量这类东西：只展示**名称与类型**，取值一律不显示，并在页面上说明「取值在部署侧 `.env`，本图不展示」。

## 5. 复现性验收

```bash
PYTHONHASHSEED=1   <build> && cp out /tmp/a
PYTHONHASHSEED=99999 <build> && cmp /tmp/a out   # 只允许日期戳不同
```

不一致 → 有地方在迭代 `set` / `dict` 的无保证顺序。行序、卡片序、表格行序都算。

再跑：`validate_diagram.py`（退出码 0）+ `leak_scan.py`（命中 0）。三个都绿才叫「可复现」。

## 6. 交底模板

产物页脚和汇报结尾各放一份，四条起步：

1. 只做了静态解析：没连系统、没跑运行时，变量实际取值 / 模型实际输出 / 接口实际返回均未核实
2. 布局是重排的（最长路径 + 重心法），不是原画布坐标，照抄会让连线穿过节点
3. 边界之外的子图（外部 workflow 工具、跨仓库调用）不在这张图里，本图到边界为止
4. 图内无消费者 ≠ 无人使用：图外的前端与日志可能是消费者，需要另证
5. 未核实任何环境是否部署了这个版本

交底不是免责声明的装饰——它决定读者会不会把图当成真相的全部。
